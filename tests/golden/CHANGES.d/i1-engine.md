# Golden ledger: i1-engine (Wave 3a integration: engine)

i1-engine regenerated nothing (goldens are regenerated by i1-reconcile). These entries explain the diffs that the
engine changes of Wave 3a cause in goldens that contain **analysis output** of the v2 pipeline
(`analyze_run` / `analyze_report`): the run-root `analysis/` files under `collectors-v0/{single,all}/**` and
`legacy/all_mode_main/**`. The data diffs of the domain analyzers themselves are in the e-net, e-data, e-compute,
e-k8s, e-rules, e-core and e-policy ledgers.

## `legacy/<scenario>/` can no longer be produced by `analyze()` (D-53)
- Findings: F-084, F-137
- Goldens: `legacy/<scenario>/**` (`tests/python/golden/test_legacy_goldens.py`), the characterisations in
  `golden/test_ir_blast_characterization.py` and `engine/eval/test_characterize_rules.py::test_microbench_baseline`
- Change: the d13c215 `analyze(report_path)`, `engine/legacy_api.py`, the legacy adapter and every verbatim d13c215
  analyzer body were removed (owner directive, Wave 3a). `tests/support/targets.engine_analyze()` raises
  `LookupError`. Old report layouts are analysed natively by `analyze_report` (`aws-enumerator analyze <dir>`).
- Expected diff: i1-reconcile retires these goldens or regenerates them from `analyze_report` (the native analysis
  of the same scenario trees: the D-22 file set, every legacy relationship file rendered from `graph.json`). There
  is no d13c215 output left to compare against.

## Five new edge types and the network analyzer (D-52)
- Findings: F-105, F-116
- Goldens: `collectors-v0/{single,all}/**/analysis/{graph,findings,summary}.json`,
  `legacy/all_mode_main/**/analysis/{graph,findings,summary}.json`
- Change: `AMI_SHARED_CROSS_ACCOUNT` (ec2), `PARAM_GRANTS_CROSS_ACCOUNT` and `SSMDOC_SHARED_CROSS_ACCOUNT` (secrets),
  `LAYER_GRANTS_CROSS_ACCOUNT` + the new finding `LAMBDA-LAYER-XACCT-001` (lambda), and `VPC_CONNECTED`
  (new analyzer `network`, after `posture`; VPC props `transit_gateways` / `vpn_connections`) are emitted where the
  world shares AMIs / parameters / documents / layer versions with another account or has active peering or
  transit-gateway attachments. `generator.engine_version` is `1.1.0`; `schema_version` stays `1.0.0`.
- Expected diff: `generator.engine_version` `1.0.0` → `1.1.0`; one more `analyzer_status` entry (`network`, `ok`
  or `skipped` without VPC data); new nodes `external_account` / placeholder `vpc` where the shares or peerings name
  them; the new edges and their `edge_types` registry entries; `LAMBDA-LAYER-XACCT-001` findings and the summary
  counts that follow. The new types have no legacy name, so no per-domain legacy relationship file changes.

## Analysis reference time (D-54)
- Findings: F-162
- Goldens: `collectors-v0/{single,all}/**/analysis/{graph,findings}.json` (`IAM-KEY-AGE-001` evidence),
  `legacy/all_mode_main/**`
- Change: ages are computed at `SOURCE_DATE_EPOCH` when set (the collectors-v0 harness pins 1767225600), else at the
  run's recorded start (`run.started_at`; old layouts `run_metadata.timestamp_start` or the date directory), never at
  the wall clock. A report with no recorded time gets the gap `clock:reference-time-unknown`.
- Expected diff: `evidence.reference_time` / `age_days` of `IAM-KEY-AGE-001` (and severities derived from the age)
  equal the pinned instant; repeated runs are byte-identical apart from stripped timestamps.
